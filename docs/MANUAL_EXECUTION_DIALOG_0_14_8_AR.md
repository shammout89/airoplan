# إصلاح نافذة سجل الإنجاز — AeroPlan 0.14.8

يعالج هذا التحديث نافذة «سجل إنجاز» للمهمة اليدوية: تبقى منطقة العنوان وأزرار الحفظ ظاهرة، ويصبح التمرير داخل المحتوى وحده. أضيفت هوامش للنصوص والمستندات والأزرار، وتُمنع حركة الصفحة الخلفية أثناء فتح النافذة وتعود عند إغلاقها. تظهر حالة التخطيط بالعربية بدل approved، وتظهر رسائل الحفظ والرفض في شريط الأزرار. تتضح حالات تحميل المستندات وغيابها وفشل قراءتها.

الإنشاء والمراجعة والاعتماد وإغلاق المهمة وقواعد المستندات والعدادات كما هي. لا توجد ترحيلات قاعدة بيانات أو تغييرات لحسابات الدخول أو صلاحياتها أو إصدارات الاعتماديات. تحتفظ الحزمة بتوحيد المستخدمين السابق في 0.14.7. حزمة الإصلاح تراكمية ومختبرة فوق مصدري 0.14.6 و0.14.7، وتحافظ على ملفات التشغيل والبيئة والبيانات والأسرار والنسخ والخدمات الموجودة.

نزّل `AeroPlan-Execution-Dialog-Fix-0.14.8.zip` إلى Downloads، وشغّل Docker Desktop. نفّذ الأوامر التالية **واحدًا بعد الآخر في نافذة PowerShell نفسها**.

**1. تحقق من مصدر النظام قبل استخراج التحديث:**

```powershell
get-content -literalpath "$env:userprofile\downloads\aeroplan-docker\release.json"
```

الحزمة مخصصة للمصدر 0.14.6 أو 0.14.7. رقم هذا الملف يصف المصدر الموجود، ويُتحقق لاحقًا من إصدار الحاوية العاملة.

**2. استخرج حزمة الإصلاح فوق المجلد الحالي:**

```powershell
expand-archive -literalpath "$env:userprofile\downloads\aeroplan-execution-dialog-fix-0.14.8.zip" -destinationpath "$env:userprofile\downloads\aeroplan-docker" -force -verbose
```

**3. انتقل إلى مجلد البرنامج:**

```powershell
set-location "$env:userprofile\downloads\aeroplan-docker"
```

**4. حدّد ملف التشغيل الأساسي:**

```powershell
$aerofiles = @('-f', 'compose.yaml')
```

**5. احتفظ بإعداد الإنتاج إن وجد:**

```powershell
if (test-path -literalpath '.\compose.production.yaml') { $aerofiles = @('-f', 'compose.production.yaml') }
```

**6. احتفظ بإعدادات الخدمات والنسخ الموجودة:**

```powershell
foreach ($aeroextra in @('compose.backup.yaml', 'compose.services.yaml')) { if (test-path -literalpath $aeroextra) { $aerofiles += @('-f', $aeroextra) } }
```

الخطوات 4–6 تضبط اختيار ملفات التشغيل وقد لا تطبع شيئًا؛ هذا طبيعي.

**7. أعد البناء والتشغيل في مشروع aeroplan نفسه:**

```powershell
docker compose -p aeroplan @aerofiles up -d --build --force-recreate --wait
```

انتظر عودة مؤشر PS. لا حاجة إلى حذف صورة أو وحدة بيانات أو إعادة تهيئة المدير. يبقى ملف التشغيل الحالي محفوظًا؛ لذلك قد يبقى وسم الصورة القديم باسمه، بينما رقم البرنامج الفعلي هو الذي يعرضه الخادم:

**8. تحقق من النسخة العاملة:**

```powershell
invoke-restmethod 'http://localhost:8080/healthz' | format-list status, version, buildFingerprint
```

المتوقع `status: ok` و`version: 0.14.8` وبصمة `bff7cfc0a19525fd92f9ed9e06cfc6bb75c611ab21b80d4d004a249f0cf18515`.

اضغط Ctrl+F5، وادخل بحساب المدير أو المخطط. افتح «خطة الصيانة ← TEST-MX-001 ← الاستحقاق والتنفيذ». يجب أن يظهر عنوان النافذة وزر إغلاقها، وشريط الحفظ أسفلها. حرّك المحتوى حتى آخره؛ يجب أن تبقى الأزرار والعنوان ظاهرين، وأن تكون النصوص داخل هوامش واضحة. يجب أن تظهر «معتمد للتخطيط» بدل approved وأن يتوقف تمرير الصفحة الخلفية أثناء فتح النافذة. جرّب أيضًا نافذة متصفح ضيقة وقصيرة، ثم أغلق النافذة وتحقق من عودة تمرير الصفحة.

إذا لم تُحفظ مسودة الإنجاز بعد، استخدم بيانات الاختبار التالية على الطائرة التجريبية فقط:

| الحقل | القيمة |
| --- | --- |
| تاريخ الإنجاز | تاريخ اليوم الظاهر |
| FH / FC عند الإنجاز | 1000 / 500 |
| مرجع أمر العمل | TEST-WO-001 |
| منفذ العمل حسب السجل | TEST-TECH-001 |
| طريقة الإثبات | سجل إنجاز داخلي |
| الملاحظات | بيانات اختبار اصطناعية |

احفظ مسودة الإنجاز وتحقق من ظهور رسالة الحفظ في الشريط السفلي. إذا كانت هناك مسودة محفوظة بالفعل، راجع بياناتها الموجودة بدل إعادة إدخالها. تبقى المهمة مفتوحة حتى إرسال الإنجاز ومراجعته واعتماده استقلالًا. لا تُنشأ مرة آلية تالية للمهمة اليدوية.
