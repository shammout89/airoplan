# AeroPlan 0.16.0 — بيانات الشركة وبدء الاستخدام

يضيف هذا الإصدار شاشة تساعد المالك على تجهيز النظام لعميل جديد، ويصحح وصف تصدير البيانات المحملة في الواجهة. يحتفظ بمزايا 0.15.0 وقواعد حساب الاستحقاقات والحسابات والمصادقة والاعتماد القائمة.

## ما الذي تغير؟

- تظهر بطاقة «جهّز شركتك وابدأ العمل» في الصفحة الرئيسية للمالك.
- يفتح «الإعدادات ← بيانات الشركة وبدء الاستخدام» نموذج اسم الشركة والقسم ومرجع البيانات وسبب الحفظ.
- يظهر اسم الشركة في مساحة العمل، ويُحفظ تاريخ تغيير البيانات. التعديل للمالك فقط؛ دور مدير النظام وحده لا يمنح هذا الحق.
- توضح ست خطوات تجهيز القوائم والفريق والطائرات والبرامج والسياسة والنسخ والقبول. الأعداد مؤشرات إدخال؛ لا تثبت صحة بيانات شركة أو اكتمال قبولها.
- يوضح «تصدير البيانات» عدد الطائرات والمهام المحملة وإجمالي المهام. ملف «بيانات العرض الحالي» يخص السجلات المحملة، وتظهر داخله حدود التصدير. يصل المالك من القائمة نفسها إلى النسخ الكاملة مع المرفقات.

مثال: إذا كانت الشركة تملك 53 مهمة وكانت الصفحة تحمل 50، يوضح التصدير أن الملف يحتوي على الخمسين المحملة. النسخ الكامل والاستعادة لهما مسارهما المخصص.

## تحديث تثبيت قائم من 0.15.0

حزمة `AeroPlan-Update-0.16.0.zip` مجربة كتحديث لمصدر 0.15.0 المرفق في هذه المحادثة. تحفظ ملفات التشغيل والبيئة والبيانات والأسرار وإعدادات النسخ القائمة. النسخة الكاملة `AeroPlan-Docker-0.16.0.zip` متاحة أيضًا للتثبيت الجديد.

احفظ نسخة كاملة جرى التحقق منها قبل التحديث. شغّل Docker Desktop، ونزّل حزمة التحديث إلى Downloads. نفّذ الخطوات التالية بالترتيب في نافذة PowerShell واحدة.

**1. انتقل إلى مجلد البرنامج القائم:**

```powershell
Set-Location -LiteralPath "$env:USERPROFILE\Downloads\AeroPlan-Docker"
```

**2. حدد حزمة التحديث:**

```powershell
$AeroUpdate = "$env:USERPROFILE\Downloads\AeroPlan-Update-0.16.0.zip"
if (-not (Test-Path -LiteralPath $AeroUpdate -PathType Leaf)) {
    throw "Download AeroPlan-Update-0.16.0.zip into Downloads first."
}
```

**3. تحقق من إصدار المصدر قبل الكتابة:**

```powershell
$AeroSource = Get-Content -LiteralPath '.\release.json' -Raw | ConvertFrom-Json
if ($AeroSource.version -notin @('0.15.0', '0.16.0')) {
    throw "This update was verified for source 0.15.0. Check the installed source before continuing."
}
Write-Host "Source version:" $AeroSource.version
```

**4. استخرج التحديث داخل المجلد الحالي:**

```powershell
Expand-Archive -LiteralPath $AeroUpdate -DestinationPath (Get-Location).Path -Force
```

**5. احتفظ بملفات تشغيل المشروع الحالية:**

```powershell
$AeroFiles = @('-f', 'compose.yaml')
if (Test-Path -LiteralPath '.\compose.production.yaml') {
    $AeroFiles = @('-f', 'compose.production.yaml')
}
foreach ($AeroExtra in @('compose.backup.yaml', 'compose.services.yaml')) {
    if (Test-Path -LiteralPath $AeroExtra) {
        $AeroFiles += @('-f', $AeroExtra)
    }
}
```

**6. أعد بناء وتشغيل مشروع aeroplan القائم:**

```powershell
docker compose -p aeroplan @AeroFiles up -d --build --force-recreate --wait
if ($LASTEXITCODE -ne 0) {
    throw "Startup failed. Read the build and container logs before continuing."
}
```

**7. تحقق من البرنامج العامل:**

```powershell
Invoke-RestMethod 'http://localhost:8080/healthz' | Format-List status, version, buildFingerprint
```

المتوقع `status: ok` و`version: 0.16.0` والبصمة:

`dd333b06a9dcc75abf29a28b278c3c9b6eeae2211cc68a03d3926244b3899385`

إصدار ملف المصدر وحده لا يثبت تحديث الحاوية. قد يحتفظ وسم صورة Docker باسمه السابق لأن ملف التشغيل القائم محفوظ؛ يُتحقق من إصدار التطبيق عبر healthz.

## تجربة الشاشة بعد التحديث

1. ادخل بحساب المالك واضغط Ctrl+F5.
2. افتح «بيانات الشركة وبدء الاستخدام» من بطاقة البداية أو الإعدادات.
3. احفظ اسم الشركة والقسم والمرجع وسبب الحفظ؛ تحقق من ظهور الاسم الجديد في مساحة العمل وسجل التغيير.
4. افتح بيانات الشركة في تبويبين. احفظ تغييرًا في الأول ثم حاول حفظ الإصدار السابق في الثاني. يجب رفض التعارض مع إبقاء مدخلات التبويب الثاني للمقارنة. زر «تحميل آخر نسخة» يستبدل المدخلات بعد اختياره صراحة.
5. تحقق بحساب مدير غير مالك من أن قسم بيانات الشركة غير متاح للتعديل، وأنه لا يستطيع تجاوز الرفض بطلب مباشر.
6. جرّب روابط خطوات البدء. راجع الطائرات والمستخدمين والمستندات والعدادات السابقة للتأكد من بقائها.
7. افتح التصدير من خطة الصيانة، ثم ابحث عن مجموعة مهام. يجب أن يصف الملف البيانات المحملة فعلًا، وأن يميز ملف العرض عن النسخ الكاملة.
8. نفّذ تجربة النسخ والاستعادة في بيئة معزولة. استعادة بيانات الأعمال تحمي إعداد الشركة الحالي، أما استعادة النسخة المحلية الكاملة فتعيد إعدادات النسخة التي تحتويها.

تبقى المصادقة الإضافية ورموز الاسترداد وسياسات الاعتماد الحالية تحت إجراءاتها القائمة. يتطلب التحديث إعادة بناء، مع بقاء وحدة البيانات الحالية والحساب الحالي.
