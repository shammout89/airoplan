# AeroPlan 0.13.0

يتضمن الإصدار معالجة توصيات تقييم 0.12، مع بوابة قبول منفصلة لأدلة الشركة. ابدأ بدليل [مسارات العمل](WORKFLOWS_0_13_AR.md)، وراجع [ضوابط الأمن والتعافي](SECURITY_0_13_AR.md) و[نتائج التحقق](TEST_REPORT_0_13.md).

## التثبيت الجديد

فك الحزمة في مجلد مستقل. ثبّت Docker Desktop مع Linux containers على جهاز Windows المستهدف، ثم افتح PowerShell داخل المجلد الذي يحتوي `compose.yaml`:

```powershell
docker compose run --rm --build app node selfhost/admin.mjs init
.\Start-AeroPlan.ps1 -Build
docker compose ps
```

يُنشأ حساب المالك تفاعليًا دون كلمة مرور افتراضية. افتح `http://localhost:8080`، ثم أنشئ حسابات الفريق من «حسابي ← إدارة الحسابات المحلية». يستخدم المُعد والمراجع والمعتمد حسابات مختلفة.

تؤكد `http://localhost:8080/healthz` الإصدار `0.13.0`. تعيد `/readyz` حالة غير جاهزة أثناء نافذة الاستعادة. إعداد HTTPS والنسخ الخارجي وSMTP وارد في [دليل التشغيل](OPERATIONS_RUNBOOK_0_11_AR.md)، مع الإضافات الأمنية في هذا الإصدار.

## تحديث تثبيت قائم

الحزمة الكاملة مصدر تثبيت؛ فكها أولًا في مجلد منفصل. تحقق من نسخة كاملة قابلة للاستعادة قبل استبدال ملفات التطبيق، وجرّب الإصدار على نسخة مستقلة من بياناتك. احتفظ بـ`compose.yaml` المخصص وملفات `.env` و`secrets/` ومجلد البيانات وملفات Compose المولدة. لا تعِد إنشاء المالك ولا تحذف volume البيانات.

بعد نقل ملفات المصدر المراجعة إلى التثبيت القائم مع الحفاظ على إعداداته:

```powershell
.\Start-AeroPlan.ps1 -Build -Recreate
docker compose ps
```

يلتقط برنامج التشغيل إعداد HTTPS وإضافات النسخ والخدمات الموجودة. يبقى اسم image المخصص صالحًا إذا أُعيد بناؤه؛ تحقق من الإصدار من `/healthz`. لا تنفذ `docker compose down -v` على بيانات تريد الاحتفاظ بها.

لا تصدر أداة التغليف تحديثًا تراكميًا دون تحديد commit أساس موثق موجود في سجل Git. هذه الحزمة كاملة، ولا تفترض وجود مصدر التثبيت الأول أو تطابق تخصيصاته.

## إعادة الاختبارات من المصدر

على بيئة Node مناسبة للتطوير:

```bash
npm ci
npx tsc --noEmit
npm run build:docker
npm run test:docker
npm audit
npm run benchmark:docker -- outputs/load.json
npm run benchmark:recovery -- outputs/recovery.json
```

أنشئ مجلد `outputs` قبل أوامر القياس. ينشئ الاختبار قواعد وملفات اصطناعية مؤقتة وينظفها. لا يستخدم مفاتيح الشركة ولا يرسل بريدًا خارجيًا؛ تجربة SMTP ضمن المجموعة تتصل بخادم اختبار محلي.

اختبارات هذا التسليم شُغلت على Node وSQLite في Linux. لم تُشغّل Docker Desktop أو PowerShell في بيئة التسليم، وتعذر تشغيل المتصفح بسبب منع المقابس المحلية؛ تبقى هذه الفحوص ضمن قبول الجهاز المستهدف.

## قبول الشركة

أضيفت حالات القبول الخاصة بالمكتبة والحالة الافتتاحية والتجميعات ومهام الوحدات وانتقال البرنامج والقطاعات والجودة والتقارير والمصادقة والتدقيق والربط. نجاح الاختبارات الاصطناعية لا يملؤها كقبول تشغيلي. يحتاج كل نجاح تشغيلي إلى مستند منشور ومراجعة مختص وقبول مستقل، وترتبط الأدلة بالإصدار وبصمة البناء وحقبة الاستعادة.
