# تحديث الإعدادات وقوائم الطائرات — AeroPlan 0.14.0

## ما تغير

أصبح «الإعدادات» مدخلًا واحدًا أسفل الشريط الجانبي، وداخله بطاقات قابلة للبحث: البيانات الأساسية للطائرات، تهيئة النظام، الفريق والصلاحيات، سجل التغييرات، والنسخ والاستعادة. تظهر كل بطاقة بحسب صلاحية المستخدم. بقيت وحدات العمل اليومية في القائمة الرئيسية.

يدير المسؤول القوائم التالية من «الإعدادات ← البيانات الأساسية للطائرات»:

| القائمة | الارتباط | صلاحية التفويض المنفصلة |
| --- | --- | --- |
| الشركة المصنّعة | مستقلة | manage_aircraft_manufacturers |
| عائلة الطراز | شركة مصنّعة واحدة | manage_aircraft_families |
| الطراز الدقيق / Variant | عائلة واحدة | manage_aircraft_variants |
| بلد التسجيل | مستقل | manage_aircraft_countries |
| جهة الإشراف الرقابي | بلد واحد | manage_aircraft_authorities |

يمكن تعريف عدة جهات رقابية للبلد، ويحدد المستخدم جهة رئيسية واحدة في بطاقة الطائرة. القوائم فارغة في التثبيت الجديد؛ تُضاف من مصادر الشركة المعتمدة، ولا تُزرع افتراضات تنظيمية أو بيانات شركة وهمية.

تدعم الإدارة الإضافة والتعديل والتعطيل وإعادة التفعيل والبحث وعرض آخر 100 إصدار؛ تبقى الإصدارات الأقدم في قاعدة البيانات والنسخة الاحتياطية. لا يوجد حذف نهائي. يمنع الخادم نقل قيمة إلى أصل آخر بعد استخدامها في طائرة أو وجود تعريفات تابعة. يمنع التعطيل الاختيارات الجديدة؛ لا يمسح القيم السابقة. يمنع تعارض الأسماء والرموز داخل القائمة والأصل نفسه، وتُرفض الكتابة القديمة والمتزامنة المتعارضة.

يمنح دور المدير إدارة القوائم الخمس افتراضيًا. تفويض مستخدم آخر يتم من «الإعدادات ← الفريق والصلاحيات ← الصلاحيات وعقود مصادر البيانات» باختيار الصلاحيات المطلوبة وإرفاق الدليل ثم الإرسال والمراجعة والاعتماد المستقل حسب السياسة الحالية. يمكن تفويض إدارة قائمة واحدة لمشاهد دون منحه تعديل الطائرات أو إدارة الحسابات. لا يوسع هذا التفويض بقية سقف دوره، ويسري الإلغاء والانتهاء في الخادم.

## بطاقة الطائرة والتاريخ

حقول المصنع والعائلة والطراز وبلد التسجيل والجهة الرقابية قوائم قابلة للبحث. يصفّي المصنع العائلات، وتصفّي العائلة الطرازات، ويصفّي البلد الجهات الرقابية. يزيل تغيير الأصل اختياراته التابعة في النموذج؛ لا يغيّر العدادات. الحقول الأساسية موسومة بنجمة حمراء مع وصف إتاحة مناسب؛ يمكن حفظ مسودة بالتسجيل وحده. يتطلب التفعيل الجديد القوائم الخمس ومعلومات الهوية والرصيد ومصدره والتأكيد التي كانت مطلوبة سابقًا.

تحفظ الطائرة معرف كل اختيار واسمَه وإصدارَه وقت الاختيار. لا يبدل تعديل الاسم أو تعطيل القائمة أسماء الطائرات المحفوظة. تبقى بطاقات الإصدار السابق المتحقق منها صالحة عند تعديل الملاحظات دون تغيير تصنيفها؛ لا تُحوّل إلى القوائم أو تُعاد تسميتها تلقائيًا. يتطلب تغيير تصنيفها أو إعادة تفعيلها اختيار القوائم المعتمدة. تبقى بيانات العدادات والمستندات وأقفال الاستخدام وإجراءات التحقق والمراجعة السابقة.

يستخدم استيراد الطائرات أسماء أو رموزًا مطابقة للقوائم المرتبطة، أو معرفاتها الصحيحة؛ لا ينشئ تعريفات جديدة تلقائيًا. يُرفض الاسم أو الرمز الملتبس الذي يطابق تعريفين، ويُستخدم حينها معرف الاختيار أو قيمة لا تلتبس. يلزم إعداد القوائم قبل الاستيراد، وتُرفض المعاينة بعد تغيير إصدار القوائم حتى تُعاد. يحفظ الاستيراد مسودات حتى يراجع المستخدم الهوية والرصيد. أصبح زر المثال «إنشاء مسودة تدريب» لتجنب إدخال تصنيف غير معتمد.

تسافر القوائم وإصداراتها ولقطات أسماء الطائرات مع النسخ والاستعادة. يرفض التحقق تاريخًا مفقودًا أو منفصلًا أو أسماء لا تطابق الإصدار المحفوظ. تبقى نسخ الإصدار السابق التي لا تحتوي هذه القوائم مقبولة.

## تحديث تثبيتك الحالي على Windows

نزّل `AeroPlan-Settings-Update-0.14.0.zip` إلى Downloads. الحزمة تشمل التغييرات فوق آخر مصدر 0.13.0 مع إصلاح QR السابق. طبّقها داخل مجلد النظام الحالي الذي يحوي compose.yaml، ولا تنشئ مشروع Compose جديدًا. اسم المشروع المستخدم لديك هو aeroplan وحاويته aeroplan-app-1.

الحزمة الجزئية لا تحتوي compose.yaml أو .env أو البيانات أو الأسرار أو ملفات Compose المُولّدة. تحفظ الترقية الحسابات وكلمات المرور والعضوية وإعدادات المصادقة ومفاتيحها والمرفقات. يضيف الترحيل فهرسين للقوائم فقط، دون تغيير جداول الحسابات أو إعادة تهيئة المدير. يُنصح بتنزيل نسخة كاملة مشفرة من النظام قبل أي تحديث.

شغّل Docker Desktop ثم نفّذ في PowerShell:

```powershell
$ErrorActionPreference = 'Stop'
Set-Location "$env:USERPROFILE\Downloads\AeroPlan-Docker"
Expand-Archive -LiteralPath "$env:USERPROFILE\Downloads\AeroPlan-Settings-Update-0.14.0.zip" -DestinationPath . -Force
.\Start-AeroPlan.ps1 -Build -Recreate
if ($LASTEXITCODE -ne 0) { throw 'لم ينجح تشغيل AeroPlan؛ راجع سجل Docker.' }
Invoke-RestMethod 'http://localhost:8080/healthz'
Start-Process 'http://localhost:8080'
```

يفحص Start-AeroPlan.ps1 ملفات الإنتاج والخدمات والنسخ الموجودة ويعيد استخدامها. يستخدم اسم aeroplan الموجود في الإعداد؛ إذا سبق تخصيص COMPOSE_PROJECT_NAME في بيئتك، أبقه على اسم التثبيت الحالي. أبقِ مجلد النظام ووحدة بياناته الحاليين، ولا تشغّل init مرة أخرى أو أوامر حذف وحدات التخزين. قد يظل اسم صورة Docker في compose.yaml هو 0.13.0 لأن الحزمة تحفظ هذا الملف؛ الإصدار الفعلي الصحيح يظهر في /healthz على أنه 0.14.0 بعد إعادة البناء.

بعد التشغيل حدّث المتصفح بـ Ctrl+F5، ثم اختبر الدخول بحسابك الحالي. افتح الإعدادات، أضف تعريفات من مصدر موثوق، واختبر القوائم المترابطة وحفظ مسودة وتفويض مستخدم لقائمة واحدة. راجع قائمة القبول الجديدة «الإعدادات وقوائم الطائرات المرتبطة» داخل النظام. الحزمة الكاملة مخصصة لتنزيل المصدر كاملًا؛ استخدم الحزمة الجزئية لتحديث إعدادك الموجود.

## التحقق وحدوده

نجح فحص TypeScript وبناء الإنتاج وجميع مجموعات الانحدار الـ32، ومنها 99 فحص قوائم وصلاحيات وتاريخ واستيراد واستعادة، و56 فحص عرض ساكن وحالة مكونات الواجهة، و16 فحص ترقية تثبيت سابق، و164 فحص HTTP فعلي، و57 فحص مصادقة. بقيت ملفات تشغيل المصادقة وQR السابقة مطابقة للمصدر السابق.

تعذر تشغيل Chromium قبل فتح أي صفحة بسبب منع socket في المضيف. لم يُنفّذ تفاعل بصري في متصفح أو بناء هذه النسخة على Windows/Docker؛ تبقى هذه الفحوص والقبول ببيانات الشركة معلقة. لا تعني الاختبارات الاصطناعية قبولًا تشغيليًا نهائيًا. الأدلة في docs/proof/settings-0.14-2026-11-16/.
