# تصحيح ظهور خيارات الطائرة — AeroPlan 0.14.3

النسخة 0.14.2 تعمل على جهازك وفق نتيجة الصحة التي أرسلتها. أُعيد إنتاج عطل مستقل في العرض: وصلت الخيارات من الإعدادات إلى مكوّن القائمة، لكن طبقتها كانت خلف نافذة إضافة الطائرة. التصحيح يضع نافذة الخيارات فوق النموذج صراحة، ويضيف تنسيق العرض والتمرير دون الاعتماد على أصناف CSS غير مولّدة.

الحزمة AeroPlan-Popup-Fix-0.14.3.zip مخصصة لتحديث 0.14.2 القائم. تحافظ على compose.yaml وملفات البيئة والبيانات والأسرار وملفات الخدمات المولّدة. لا تغييرات على الترحيلات أو الحسابات أو المصادقة أو الصلاحيات. لا حاجة لتهيئة المدير مجددًا.

## التطبيق

نزّل الحزمة إلى Downloads، وشغّل Docker Desktop. نفّذ كل سطر منفردًا واضغط Enter؛ لا يستدعي هذا المسار ملف PowerShell غير موقّع.

```powershell
Expand-Archive -LiteralPath "$env:USERPROFILE\Downloads\AeroPlan-Popup-Fix-0.14.3.zip" -DestinationPath "$env:USERPROFILE\Downloads\AeroPlan-Docker" -Force -Verbose
Get-Content "$env:USERPROFILE\Downloads\AeroPlan-Docker\release.json"
```

يجب أن يعرض الملف 0.14.3؛ توقف إذا فشل الاستخراج.

```powershell
Set-Location "$env:USERPROFILE\Downloads\AeroPlan-Docker"
$AeroFiles = @('-f', 'compose.yaml')
if (Test-Path '.\compose.production.yaml') { $AeroFiles = @('-f', 'compose.production.yaml') }
foreach ($AeroExtra in @('compose.backup.yaml', 'compose.services.yaml')) { if (Test-Path $AeroExtra) { $AeroFiles += @('-f', $AeroExtra) } }
docker compose -p aeroplan @AeroFiles up -d --build --force-recreate --wait
Invoke-RestMethod 'http://localhost:8080/healthz' | Format-List status, version, buildFingerprint
```

أسطر تجهيز المعاملات لا تطبع نتائج عادة؛ أمر Docker يطبع تقدم البناء والتشغيل. انتظر عودة مؤشر PS، وتحقق من status = ok وversion = 0.14.3. قد يبقى وسم الصورة قديمًا لأن إعداد التشغيل محفوظ؛ الإصدار في healthz هو إصدار التطبيق الفعلي. البصمة المتوقعة: 88f56ca0d59d25e1e1dafa03f62132f66cfc2b862fbeec54afa8f9a04fb45c40.

اضغط Ctrl+F5 في المتصفح، وافتح إضافة طائرة. اختر الشركة المصنّعة قبل عائلة الطراز، والعائلة قبل الطراز الدقيق؛ اختر بلد التسجيل قبل الجهة الرقابية. تظهر القيم النشطة المرتبطة بالأصل المختار من تبويبات الإعدادات. اختبر البحث والاختيار بالماوس ولوحة المفاتيح، وتأكد أن قائمة الخيارات فوق النافذة وأن السهم داخل الصندوق. جرّب العرض الضيق، وتغيير قيمة في الإعدادات ثم فتح النموذج أو العودة إلى تبويبه.

احتفظ بحسابك ووحدة البيانات الحالية. لا تستخدم down -v أو حذف وحدة البيانات أو init كخطوة تحديث. عند تعثر البناء أو استمرار العطل، احتفظ بمخرجات healthz ورسالة الخطأ؛ لا تُعدّ عملية الاستخراج وحدها تحديثًا للخادم العامل.

## ما اختُبر

نجحت 47 حالة تفاعل لمكوّنات React الفعلية في JSDOM على API/SQLite حقيقيين مع CSS الإنتاج: إنشاء القوائم الخمس وروابطها من نماذج الإعدادات، ظهور الخيارات خارج غطاء النافذة وفوقه، البحث والاختيار بلوحة المفاتيح والنقر على الخيارات، مسح البلد وما يتبعه، وحفظ طائرة مفعّلة بالمعرفات المختارة. فتح القائمة في هذه المحاكاة يتم بلوحة المفاتيح؛ ليست اختبارًا لعمل زر السهم بالماوس في متصفح فعلي.

نجح التثبيت المقفل وTypeScript وبناء الإنتاج وكل مجموعات الانحدار الـ34. أُضيفت ثلاث أدوات اختبار مثبتة الإصدارات كاعتماديات تطوير، وبقيت سجلات اعتماديات الإنتاج السابقة مطابقة. لم يُشغل تدقيق npm جديد. يتطلب اختبار DOM بيئة Node 24.15+ أو 22.22.2+؛ اختُبر على 24.22.1، ويستخدم Docker المشروع Node 24.

لم ينفذ هنا فحص بكسلات متصفح أو تشغيل Windows/Docker على جهازك. تبقى تجربتك بعد التحديث مطلوبة لإثبات النتيجة على الجهاز المستهدف. الأدلة في docs/proof/popup-0.14.3-2026-11-16/.
