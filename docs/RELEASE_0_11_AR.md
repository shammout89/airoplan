## التحديث على Windows

خذ نسخة من بيانات العمل من إصدارك الحالي أولًا. حزمة التحديث تراكمية للإصدار الأصلي 0.9 وللتحديثات 0.9.1/0.9.2/0.10.0. فك محتوياتها **داخل مجلد AeroPlan-Docker الحالي** مع استبدال ملفات البرنامج. لا تحذف مجلد المشروع أو Docker volume. الحزمة لا تستبدل `.env` أو `compose.yaml` أو بياناتك أو أسرارك أو ملفات Compose التي سبق توليدها.

شغّل هذا السطر وحده من مجلد المشروع:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Start-AeroPlan.ps1 -Build
```

ثم افتح الرابط المعتاد وحدّث الصفحة بـ Ctrl+F5. ملف `release.json` مصدر واحد لرقم الإصدار، ويظهر 0.11.0 في واجهة التطبيق وترويسات HTTP والصحة. يُطبق التحديث فهرس 0009 دون تغيير ترحيلاتك السابقة أو حذف بياناتها.

فحص النسخة المشغلة:

```powershell
curl.exe -s http://localhost:8080/healthz
```

للتثبيت الجديد استخدم الحزمة الكاملة ثم شغّل سطر البدء نفسه، وبعد البناء أنشئ المدير بسطر مستقل:

```powershell
docker compose run --rm app node selfhost/admin.mjs init
```

أدخل بريدًا إلكترونيًا صحيحًا، ثم الاسم وكلمة مرور من 12 محرفًا أو أكثر. بعد التهيئة شغّل سطر البدء مرة أخرى. عند استخدام HTTPS استبدل رابط الفحص برابط نطاقك.

## ما ينبغي فتحه أولًا

1. «اختبارات القبول»: تبقى حالة الإصدار غير مقبول حتى إدخال ومراجعة كل حالة شركة وإقرار المالك. النتائج السابقة محفوظة بتاريخ إصدارها.
2. «النسخ والاستعادة»: هيئ الوجهة والمفتاح ثم تحقق من أول نسخة ومن الاستعادة المعزولة.
3. «التكاملات ومراقبة التشغيل»: حمّل عقد الاتصال وافحص الاستقبال. اترك الترحيل التلقائي معطلًا حتى مطابقة النتائج.
4. «المتابعة والبريد»: راجع المستلمين والطابور وسبب أي رسالة غير مؤكدة.
5. «الاعتمادية والاتجاهات»: اختر فترة وافحص جودة البيانات قبل تفسير المعدلات.

النسخة ليست تصريح صلاحية للطيران أو بديلًا عن إجراءات الشركة والجهة المختصة. تسجيل استخدام وقع فعليًا لا يجيز الإقلاع مع قيد عطل، ويستلزم توثيق استثناء ظاهر عند وجود قيود.

راجع `OPERATIONS_RUNBOOK_0_11_AR.md` و`INTEGRATION_CONTRACT_0_11.md` لتفاصيل الإعداد والتعافي.
