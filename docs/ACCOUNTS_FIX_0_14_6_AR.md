# تحديث إنشاء الحسابات — AeroPlan 0.14.6

تضيف الحزمة إلى «حسابي ← إدارة الحسابات المحلية ← إضافة مستخدم» حقلي **كلمة المرور** و**تأكيد كلمة المرور** وزر **إنشاء الحساب وتفعيله**. يصبح الحساب الجديد جاهزًا للدخول فور إنشائه، دون المرور برابط تفعيل. الطول المقبول من 12 إلى 128 حرفًا، ويجب تطابق الحقلين. لا تظهر كلمة المرور مجددًا في الرد أو قائمة الحسابات.

يبقى إنشاء الحساب برابط تفعيل خيارًا منفصلًا مطويًا أسفل النموذج. وتستمر الروابط الصادرة سابقًا وإعادة الضبط وحسابات الفريق والصلاحيات والمصادقة الثنائية. لا توجد ترحيلات جديدة أو إعادة كتابة لبيانات قائمة. إصلاحات الطائرة والقوائم والتواريخ والحفظ السابقة ضمن هذه الحزمة التراكمية.

نزّل `AeroPlan-Accounts-Fix-0.14.6.zip` إلى Downloads. أبقِ مجلد النظام الحالي وشغّل Docker Desktop. نفّذ الأوامر التالية **واحدًا بعد الآخر في نافذة PowerShell نفسها**. لا تُعِد تهيئة المدير، ولا تحذف بيانات Docker.

**1. التحقق من ملفات المصدر الموجودة:**

```powershell
get-content -literalpath "$env:userprofile\downloads\aeroplan-docker\release.json"
```

الحزمة مختبرة فوق مصادر 0.14.3 و0.14.4 و0.14.5. هذا الملف يحدد نسخة المصدر، وليس بالضرورة نسخة الحاوية التي تعمل الآن.

**2. استخراج التحديث فوق المجلد الحالي:**

```powershell
expand-archive -literalpath "$env:userprofile\downloads\aeroplan-accounts-fix-0.14.6.zip" -destinationpath "$env:userprofile\downloads\aeroplan-docker" -force -verbose
```

**3. الدخول إلى المجلد:**

```powershell
set-location "$env:userprofile\downloads\aeroplan-docker"
```

**4. اختيار ملف التشغيل الأساسي:**

```powershell
$aerofiles = @('-f', 'compose.yaml')
```

**5. الاحتفاظ بإعداد الإنتاج إن وجد:**

```powershell
if (test-path -literalpath '.\compose.production.yaml') { $aerofiles = @('-f', 'compose.production.yaml') }
```

**6. الاحتفاظ بملفات النسخ والخدمات إن وجدت:**

```powershell
foreach ($aeroextra in @('compose.backup.yaml', 'compose.services.yaml')) { if (test-path -literalpath $aeroextra) { $aerofiles += @('-f', $aeroextra) } }
```

الأوامر 4–6 تحدد إعداد التشغيل وقد لا تطبع شيئًا؛ هذا طبيعي.

**7. إعادة البناء والتشغيل في مشروع aeroplan نفسه:**

```powershell
docker compose -p aeroplan @aerofiles up -d --build --force-recreate --wait
```

انتظر اكتمال البناء وعودة مؤشر PS قبل الأمر التالي. لا حاجة إلى إيقاف النظام أو حذف الصورة أو وحدة البيانات مسبقًا. تحفظ الحزمة ملف التشغيل والبيئة وملفات الخدمات والنسخ الموجودة؛ لذلك قد يحتفظ وسم الصورة القديم باسمه رغم تحديث البرنامج. الحكم على الإصدار من الخادم:

**8. التحقق من النسخة العاملة:**

```powershell
invoke-restmethod 'http://localhost:8080/healthz' | format-list status, version, buildFingerprint
```

المتوقع `status: ok` و`version: 0.14.6` وبصمة `d18fb89c9427191ceac8cd5a107649a28f921faebdb3c437a1f2423874840557`.

ادخل بحساب المالك الحالي، واضغط Ctrl+F5، ثم افتح [إدارة الحسابات المحلية](http://localhost:8080/auth/admin). يجب أن تظهر كلمة المرور وتأكيدها في النموذج الأساسي.

| الاسم | بريد اختبار محلي | الدور |
| --- | --- | --- |
| مراجع الاختبار | reviewer@aeroplan.test | مراجع |
| معتمد الاختبار | approver@aeroplan.test | معتمد |

اختر كلمة مرور خاصة بكل حساب؛ لا ترسلها في المحادثة. بعد «إنشاء الحساب وتفعيله»، سجّل الخروج ثم ادخل بالبريد وكلمة المرور اللذين اخترتهما. إنشاء الحساب لا يبدّل جلسة المدير تلقائيًا. تظل سياسة المصادقة الثنائية الحالية نافذة إن كانت إلزامية للدور.

إذا كان الحساب قد أُنشئ سابقًا وينتظر التفعيل، فلن يستبدله إنشاء حساب مكرر. استخدم رابط تفعيله السابق، أو زر «إعادة ضبط» لإصدار رابط جديد يختار منه صاحب الحساب كلمة مرور. لا تحذف العضوية لحل ذلك.

بعد الدخول، يكمل المراجع مراجعة TEST-MX-001 بعد إرسالها من مُعدّها، ثم يسجل الخروج ويدخل المعتمد لاعتمادها. يبقى الفصل بين مُعدّ المهمة ومراجعها ومعتمدها إلزاميًا. تحقق من بقاء TEST-G200-001 عند 1000 FH و500 FC ومن بقاء حدود المهمة وبياناتها السابقة.

التحقق المحلي: نجحت 37 مجموعة اختبار، منها 75 فحص حسابات و179 فحص HTTP إنتاج، واختبار ترقية فعلي من كود 0.14.5 في 44 تحققًا. البيانات المستخدمة اصطناعية. لم يُنفذ هنا تشغيل Windows/Docker أو فحص بكسلات متصفح؛ يلزم إثبات النتيجة على جهازك بعد التثبيت.
