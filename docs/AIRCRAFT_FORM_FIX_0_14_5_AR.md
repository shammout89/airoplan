# إصلاح محاذاة نموذج الطائرة وحفظه — AeroPlan 0.14.5

الحزمة AeroPlan-Aircraft-Form-Fix-0.14.5.zip تراكمية لمصدر 0.14.3 أو 0.14.4. تشمل تصحيح التواريخ السابق وتصلح حالة بقاء منع الحفظ بعد رفض إدخال خاطئ رغم رجوع الحقل لقيمة صحيحة. لا تعطل التحقق من تاريخ غير صحيح ظاهر أو ضوابط التفعيل. تنظم الحقول في عمودين على العرض الواسع وعمود واحد على العرض الضيق، وتوحد محاذاة العناوين والصناديق والإرشادات. تعرض سبب رفض الحفظ داخل النافذة، وتحفظ المدخلات وتمنع طلب تفعيل ثانٍ أثناء الحفظ.

لا تغير الحزمة الحسابات أو المصادقة أو الصلاحيات أو مخطط البيانات أو سجلات الطائرات. تحافظ على compose.yaml والبيئة والبيانات والأسرار وملفات الخدمات المولّدة. مشروع التشغيل يبقى aeroplan وحسابك الحالي محفوظ.

نزّل الحزمة إلى Downloads وشغّل Docker Desktop. نفّذ كل أمر منفصلًا في نافذة PowerShell نفسها.

**1. تحقق من مصدر البرنامج قبل الاستخراج:**

```powershell
Get-Content "$env:USERPROFILE\Downloads\AeroPlan-Docker\release.json"
```

يلزم مصدر 0.14.3 أو 0.14.4. إن كان أقدم، طبّق تحديث 0.14.3 السابق أولًا. إصدار الملف لا يثبت إصدار الحاوية العاملة.

**2. فك حزمة الإصلاح:**

```powershell
Expand-Archive -LiteralPath "$env:USERPROFILE\Downloads\AeroPlan-Aircraft-Form-Fix-0.14.5.zip" -DestinationPath "$env:USERPROFILE\Downloads\AeroPlan-Docker" -Force -Verbose
```

**3. الانتقال إلى مجلد النظام:**

```powershell
Set-Location "$env:USERPROFILE\Downloads\AeroPlan-Docker"
```

**4. تحديد ملف التشغيل:**

```powershell
$AeroFiles = @('-f', 'compose.yaml')
```

**5. الاحتفاظ بإعداد الإنتاج إن وُجد:**

```powershell
if (Test-Path '.\compose.production.yaml') { $AeroFiles = @('-f', 'compose.production.yaml') }
```

**6. إضافة ملفات الخدمات والنسخ الموجودة:**

```powershell
foreach ($AeroExtra in @('compose.backup.yaml', 'compose.services.yaml')) { if (Test-Path $AeroExtra) { $AeroFiles += @('-f', $AeroExtra) } }
```

الأسطر 4–6 قد لا تطبع نتائج؛ هذا طبيعي.

**7. إعادة البناء والتشغيل، ثم انتظار عودة مؤشر PS:**

```powershell
docker compose -p aeroplan @AeroFiles up -d --build --force-recreate --wait
```

**8. التحقق من الخادم العامل:**

```powershell
Invoke-RestMethod 'http://localhost:8080/healthz' | Format-List status, version, buildFingerprint
```

المتوقع status = ok وversion = 0.14.5 والبصمة 3c1bfdc7ecdb3851fad9b3c4004a4933e2a7e7eec4148df13af9845cd870a715. قد يبقى وسم الصورة قديمًا لأن ملف تشغيلك محفوظ. لا إعادة init أو حذف وحدة البيانات.

اضغط Ctrl+F5 وافتح إضافة طائرة. تحقق من محاذاة العناوين والقوائم ووجود الإرشادات أسفلها دون تحريك بقية الحقول. جرّب عرضًا ضيقًا. يمكن حفظ المسودة بتسجيل فريد فقط. لتفعيل التخطيط أكمل الهوية والقوائم الخمس والعدادات ومرجعها وحالة الأسطول والتأكيد؛ ستظهر رسالة واضحة داخل النافذة عند وجود نقص أو تعارض. إذا رُفض إدخال تاريخ وبقيت قيمة صحيحة ظاهرة، يجب أن تعمل محاولة حفظ تلك القيمة الصحيحة دون بقاء منع قديم. التاريخ المستحيل أو المستقبلي الظاهر يبقى ممنوعًا حتى تصحيحه.

في مسودة اختبار منفصلة، تحقق من الحفظ وإعادة ظهور الطائرة، ومن اختيار القوائم الخمس وتفعيل التخطيط عند استيفاء البيانات. تحقق أيضًا من بقاء الساعات والدورات والملاحظات والسجلات السابقة. بُني الإصلاح واختُبر برمجيًا عبر Page الفعلي وAPI/SQLite وCSS الإنتاج؛ لم يُنفذ تحقق بكسلات متصفح أو تشغيل Windows/Docker على جهازك هنا.
